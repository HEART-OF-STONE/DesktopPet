## 1. 参考项目实际提供什么

已重新核对 [README](https://github.com/MeteorNOX/DeepSeek-Balance-Whale-Widget#readme) 与 [宿主源码](https://github.com/MeteorNOX/DeepSeek-Balance-Whale-Widget/blob/main/lib/index.js)：

| 能力 | 参考项目的实现与边界 |
|---|---|
| DSH Agent 联动 | 监听 `session/event`，聚合 `assistant/message` 的 usage，在 `turn/end` 结算；按会话区分主会话和子代理 |
| 任务完成反馈 | 每轮结束显示消耗气泡，可配结束音 |
| DeepSeek 余额 | API 查询、定时/手动刷新、余额预警 |
| 今日与历史用量 | 余额差记账，会话事件金额兜底；明细、归档和预算提醒 |
| 多厂商 | 提供余额/额度模板；模板不意味着厂商都提供可查询余额 |
| Codex 模式 | 只读 `$CODEX_HOME/sessions` 和 `archived_sessions` 中 JSONL，按日期与模型统计 token |
| Codex 订阅窗口 | 从日志读取 `rate_limits` 快照；作者注明无真实订阅样本充分验证，缺失时不显示 |
| 自定义内容 | 气泡模块、点击队列、随机内容、图片、声音等 |

该项目是 DSH Web 插件，Codex 是其数据来源之一；未提供安装进 Codex 的桌宠。当前桌边是独立 Windows 桌宠，需自己的数据适配层。

## 2. V1 新增目标

### A. Codex 优先

- 展示任务运行、完成、失败以及可识别的待审批状态，并触发桌宠动作/气泡。
- 展示 token 统计、统计范围、时间段、模型和数据更新时间。
- 展示服务返回的额度窗口与重置时间，窗口名称按实际时长生成，避免固定假设只有 5 小时和每周两个桶。
- 离线、接口缺失或过期时显示“不可用”或“最后更新于…”，不把无数据当零余额。
- 多任务完成做合并提示；历史补读不重放所有完成提醒。

接入路线先做兼容性验证：

1. **公开 App Server 接口**：优先验证 `account/rateLimits/read`；当前官方文档也提供 `account/usage/read`，具体支持取决于认证类型和本机版本。[官方文档](https://learn.chatgpt.com/docs/app-server)
2. **已有任务事件**：验证公开事件订阅与 Hooks 是否能覆盖用户当前桌面版的任务，而不只覆盖桌宠自行启动的会话。Hooks 可提供完成/审批等生命周期入口，具体客户端和配置需实测。[官方 Hooks 文档](https://learn.chatgpt.com/docs/hooks)
3. **本地日志兼容适配**：用量明细可作为后备来源，仅读取选定目录所需字段；不把 JSONL 私有格式当作永久协议。先用合成样本验证，再用明确范围的本机样本核对。

本次只检查本机 CLI 帮助，版本为 `0.154.0-alpha.6.2`，存在 `app-server` 命令；尚未运行接口、修改 Codex 配置或读取会话内容。当前对话中 Codex 自带的工具能力不等于桌宠进程已获得相同接口。

### B. 余额、额度和账本

- 第一家实际余额源优先 DeepSeek；按用户实际使用的平台再加其他适配器。
- 展示币种、余额、查询时间、错误状态、低余额提醒和每日预算提醒。
- 将 **账户余额、订阅窗口百分比、token 数量、估算费用** 分别存储与展示。
- 估算费用附单价版本和统计来源。余额下降可能包含其他应用的消耗，不能直接标记为当前任务成本。
- 不同来源交叉核对，账本不能把余额差和事件估算重复相加。
- 密钥使用系统凭据存储；角色配置、导出设置和日志不包含密钥。

### C. 通用 Agent 联动

- 统一事件字段：来源、会话、轮次、事件 ID、时间、状态、可选用量和摘要。
- 先完成 Codex 适配，再依用户实际使用情况接入 DSH、Claude Code 或其他工具；不承诺未验证的平台兼容。
- 本地接收入口需要配对或访问控制，限制消息长度、频率与事件类型。事件只能触发约定的桌宠行为。
- 免打扰、气泡队列、优先级和事件去重共用现有桌宠基础功能。

必须覆盖：累计 token 重复事件、累计量回退、缓存/推理 token 的包含关系、多任务同时结束、程序重启后的去重、日志半行与轮转、接口断线/失效、缺少额度字段、手动刷新、预警冷却、数据源重叠。

完成标准：在用户日常使用的 Codex 任务中可观测并触发桌宠反馈；用量与额度能对照来源核验；至少一家用户实际配置的余额源能够查询并提醒。缺少凭据时可以交付可配置适配器，但不能标记真实账户联调通过。

## 4. 与后续 AI 的关系

Agent 联动让桌宠呈现已有工具的工作状态与用量；内置 AI 聊天让用户直接和桌宠交流，两者分别排期。V1 先补联动与看板，M4 再做聊天/记忆，M5 再做 Live2D。
