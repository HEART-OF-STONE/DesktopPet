# 安装目录验证 · 2026-09-28

## 行为

首次安装保留 Tauri NSIS 的目录选择页。默认使用当前用户的 LocalAppData，允许选择可写的其他目录。手动更新通过产品注册项恢复上次路径；应用内更新在最后一个安装器参数传入未加引号的 `/D=当前程序目录`，明确覆盖旧记录。设置页显示同一目录。

用户数据目录没有迁移。免安装副本更新后在原目录转为安装版，后续通过安装后的快捷方式启动。当前公开 v0.9.2 的更新发起逻辑不会被这次源码修改追溯改变；新行为需先使用包含修复的新版本。

## 验证结果

- 前端 TypeScript / Vite 构建通过；53 项 Rust 测试通过，含中文、空格、盘符根目录、UNC 和 Windows verbatim 前缀处理。
- 独立 `DesktopPet Location Test` 安装器完成：自定义中文空格目录安装、无 `/D` 时恢复目录、注册项过期时显式 `/D` 覆盖、未写默认安装目录、无关文件保留、卸载清理。追加 0.9.2 → 0.9.3 跨版本覆盖验证，程序文件和注册的版本号均符合预期。
- 实际打开隔离安装器的目录页，验证默认 LocalAppData 路径可编辑为 E 盘中文空格目录，随后取消。正式 0.9.3 使用相同目录页配置，生成的 NSIS 脚本已核对。
- 卸载时 NSIS 默认保留目录记忆，只有勾选删除数据才会一起删除。这不是程序残留；测试脚本核对目标后仅清理本轮独立测试的记忆注册项。
- 未启动测试产品读取用户日志，也未覆盖正式产品或公开安装包。
- 公开源码检查通过；测试产物保存在忽略的 `.cache` / `target` 目录。

## 复现

使用 PowerShell 运行 `npm run desktop:build -- --ci --bundles nsis --config scripts/fixtures/tauri-location-test.json`，然后执行 `scripts/test-install-location.ps1`。可用 `-PreviousVersion 0.9.2` 指定已保留的隔离旧版安装器执行跨版本验证。测试前要求无同名测试产品和正在运行的 `desktop-pet.exe`。

受限环境若构建前端命令不可用，可先 `npm run build`，再用仅存在于本机 `.cache` 的配置覆写 `build.beforeBuildCommand` 为空。

## 验证边界

前次界面自动化授权超时，本次已补齐目录编辑检查。安装验证使用独立测试产品；不代表真实用户的 GitHub 下载、安装器接管、自动重启完整链路已验收。正式成品另以隔离数据验证设置页路径、版本，以及三种布局的七种任务状态。
