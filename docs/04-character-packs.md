# 角色包协议 v1

适用版本：桌边 v0.1.0 原型。这里描述已实现的字段；架构规划中的预览、锚点、表情、Live2D 字段暂未启用。

## 1. 导入方式

进入「角色衣橱 → 导入角色」，选择一张 PNG，或同时选择 **一个 JSON 清单及其引用的全部 PNG 文件**。不需要安装插件，不执行角色脚本。

当前选择普通文件，不直接读取文件夹或 ZIP。清单引用同目录文件名，不写绝对路径或子目录。PNG 文件名支持中文，资源键和皮肤 ID 使用字母、数字、下划线或短横线。

示例：

- `examples/png-sequence/`：12 张独立图片，包含中文文件名，展示帧顺序与缺少动作时的待机回退。
- `examples/sprite-sheet/`：两张精灵图，分别提供待机与摸头动作。
- `public/pets/cream/portrait.png`：可单独导入为静态角色。

## 2. 最小静态角色

单 PNG 导入会自动生成下面形式的清单；要制作多皮肤角色，也可以自己编写：

```json
{
  "schemaVersion": 1,
  "name": "我的伙伴",
  "description": "今天也陪着你",
  "author": "你的名字",
  "license": "填写真实的素材授权说明",
  "renderer": "static",
  "width": 256,
  "height": 256,
  "skins": [{
    "id": "default",
    "name": "默认装扮",
    "color": "#e9dcc3",
    "assets": { "portrait": "角色.png" }
  }],
  "actions": {
    "idle": {
      "frames": [{ "asset": "portrait" }],
      "fps": 1,
      "loop": true
    }
  }
}
```

导入后，应用生成独立的 `custom-...` ID。`id` 不是需要作者指定的字段。`width` / `height` 是固定绘制画布；单张图会保持比例居中显示。建议所有动作素材使用相同尺寸与角色落脚位置。

## 3. PNG 序列与精灵图

逐帧角色设置 `renderer: "sprite"`，在 `skins[].assets` 中给图片命名，再按顺序列出帧。

独立 PNG：

```json
{
  "frames": [
    { "asset": "frame1" },
    { "asset": "frame2" },
    { "asset": "frame3" }
  ],
  "fps": 12,
  "loop": true
}
```

这里的 `frame1` 等键对应 `assets: { "frame1": "01.png", "frame2": "02.png", "frame3": "03.png" }`。顺序取自清单，不取决于文件名排序。

精灵图裁切：

```json
{
  "frames": [
    { "asset": "sheet", "x": 0, "y": 0, "width": 256, "height": 256 },
    { "asset": "sheet", "x": 256, "y": 0, "width": 256, "height": 256 }
  ],
  "fps": 12,
  "loop": true
}
```

此时 `assets: { "sheet": "idle.png" }`。矩形单位是图片像素，必须完全落在对应图片内；裁切后的帧绘制到统一画布。

动画按经过时间选择帧，不依赖显示器刷新率。`loop: false` 播放一次后回到 `idle`。目前互动通常在 4.2 秒后结束，休息在 7 秒后结束；较长动画可能被这一行为时长截断，因此原型角色建议动作不超过此时长。

## 4. 六种动作

| 键 | 触发 | 必需 |
|---|---|---|
| `idle` | 待机、动作缺失时回退 | 是，建议循环 |
| `pet` | 摸头、桌宠轻点 | 否 |
| `happy` | 小零食 | 否 |
| `sleepy` | 休息 | 否 |
| `drag` | 桌宠拖动结束后的反馈 | 否 |
| `celebrate` | 庆祝、专注完成 | 否 |

缺少某动作时继续显示待机资源，保留通用的程序变形和气泡反馈。静态模式只显示单帧，动态序列请明确选择 `sprite`。不支持自定义代码、未知动作名或 Live2D 参数。

## 5. 皮肤

在 `skins` 添加新项即可，每项都需提供相同动作所引用的全部资源键。例如默认皮肤的 `sheet` 对应 `idle-cream.png`，绿色皮肤的 `sheet` 对应 `idle-sage.png`；动作定义可以共用。

皮肤可以换颜色、服装或整套图片。精灵图必须使用相同帧布局，避免同一裁切矩形在另一套皮肤中越界。后续 Live2D 会有独立的资源适配，当前图片包不会自动转换成 Live2D 模型。

## 6. 当前限制

| 项目 | 上限 / 要求 |
|---|---|
| 自定义角色 | 6 个 |
| 单次选择 | 40 个文件，总计 12 MiB |
| JSON 清单 | 256 KiB |
| 角色名称 | 1–40 个字符 |
| 画布 | 宽、高各 16–2048 |
| 图片 | 单边不超过 8192 像素；全部 PNG 共不超过 16,777,216 像素 |
| 皮肤 | 1–4 套，每套最多 32 个资源键 |
| 动作 | 每个 1–120 帧，帧率 1–60 |
| 完整本地状态 | 桌面宿主保存上限 32 MiB，图片转为 Base64 后会增大 |

浏览器体验模式还受浏览器 localStorage 容量限制，大角色请使用桌面版。导入失败会显示原因，保留已选择的角色。图片被复制进应用数据，移除角色不会删除原始素材。
