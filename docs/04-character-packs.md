# 角色包协议 v1 / v2

角色包 v1 继续兼容。v2 在原有格式上增加独立自主动作、待机小动作和动作变体；只包含图片与声明式动画数据。锚点、独立表情图层和 Live2D 字段暂未启用。

## 1. 导入方式

进入「角色衣橱 → 导入角色」，选择一张 PNG，或同时选择 **一个 JSON 清单及其引用的全部 PNG 文件**。不需要安装插件，不执行角色脚本。

当前选择普通文件，不直接读取文件夹或 ZIP。清单引用同目录文件名，不写绝对路径或子目录。PNG 文件名支持中文，资源键和皮肤 ID 使用字母、数字、下划线或短横线。

导入后，图片与动作作为独立副本保存在应用中；修改原文件或更新内置角色不会自动改变已导入的角色。“动作试映”播放这份实际角色素材，点击“让它来陪我”即可用于桌面陪伴。

已有角色的素材需要更新时，在「角色衣橱」的对应卡片点击「更新素材」，重新选择新版 PNG 或 JSON 与全部 PNG。应用先校验完整角色包，成功后替换原角色的图片与动作，保留角色 ID、自定义名字、衣橱位置和当前选择；当前皮肤仍存在时继续使用，否则切到新版第一套皮肤。更新失败则保留原角色，不新增重复角色。普通「导入角色」仍用于添加新伙伴。

源码仓库中的示例（发布 ZIP 不包含这些开发素材目录）：

- `examples/png-sequence/`：12 张独立图片，包含中文文件名，展示帧顺序与缺少动作时的待机回退。
- `examples/sprite-sheet/`：两张精灵图，分别提供待机与摸头动作。
- `examples/motion-pack-v2/`：完整 v2 示例，包含 16 种动作、互动变体和自主行为冷却；导入时同时选择 `pet.json` 和 `pet.png`。
- `public/pets/cream/portrait.png`：可单独导入为静态角色。

## 2. 最小静态角色

单 PNG 导入会自动生成下面形式的清单；要制作多皮肤角色，也可以自己编写：

```json
{
  "schemaVersion": 1,
  "name": "我的伙伴",
  "description": "今天也陪着你",
  "author": "你的名字",
  "license": "填写真实的素材授权说明",
  "renderer": "static",
  "width": 256,
  "height": 256,
  "skins": [{
    "id": "default",
    "name": "默认装扮",
    "color": "#e9dcc3",
    "assets": { "portrait": "角色.png" }
  }],
  "actions": {
    "idle": {
      "frames": [{ "asset": "portrait" }],
      "fps": 1,
      "loop": true
    }
  }
}
```

导入后，应用生成独立的 `custom-...` ID。`id` 不是需要作者指定的字段。`width` / `height` 是固定绘制画布；单张图会保持比例居中显示。建议所有动作素材使用相同尺寸与角色落脚位置。

## 3. PNG 序列与精灵图

### 高 DPI 素材

角色清单的画布宽高是逻辑尺寸，PNG 和精灵图裁切宽高是图片像素，可以不同。例如逻辑画布 256×256、每帧 PNG 768×768，仍显示相同大小，在高 DPI 屏幕上保留更多细节。v0.5.1 内置角色及示例使用 768 像素帧，精灵图按 4 列 × 3 行排列。旧版 256 像素角色包仍可使用，但放大时清晰度受原图限制。

本轮内置素材使用 512 像素帧，并按各动作的实际时长分配帧数；布局由 `src/core/builtinMotions.json` 统一描述。完整 v2 导入示例使用 512 像素待机帧与 256 像素动作帧，重复画面共用同一裁切区域，打包进不超过 4096×4096 的共享图集。示例保留 16 种动作、全部变体和原有时长；缓慢呼吸与打瞌睡减少采样，主要互动约 7.5 FPS，快速眨眼和耳朵动作保持原帧率，以满足 16 Mi-pixel 的导入预算。内置动画保持原帧率。SVG 按目标分辨率直接栅格化，避免先生成小图再放大；定制角色可以按显示大小和屏幕像素密度，在预算内安排分辨率与帧数。

Canvas 自动匹配显示大小与屏幕像素密度；为限制内存，最多按 4 倍密度绘制，绘制缓冲最长边不超过 2048 像素。素材像素与导入数量限制仍适用。

逐帧角色设置 `renderer: "sprite"`，在 `skins[].assets` 中给图片命名，再按顺序列出帧。

独立 PNG：

```json
{
  "frames": [
    { "asset": "frame1" },
    { "asset": "frame2" },
    { "asset": "frame3" }
  ],
  "fps": 12,
  "loop": true
}
```

这里的 `frame1` 等键对应 `assets: { "frame1": "01.png", "frame2": "02.png", "frame3": "03.png" }`。顺序取自清单，不取决于文件名排序。

精灵图裁切：

```json
{
  "frames": [
    { "asset": "sheet", "x": 0, "y": 0, "width": 256, "height": 256 },
    { "asset": "sheet", "x": 256, "y": 0, "width": 256, "height": 256 }
  ],
  "fps": 12,
  "loop": true
}
```

此时 `assets: { "sheet": "idle.png" }`。矩形单位是图片像素，必须完全落在对应图片内；裁切后的帧绘制到统一画布。

动画按经过时间选择帧，不依赖显示器刷新率。逐帧角色的 `loop: false` 动作按实际帧数和帧率播放一次，结束后回到 `idle`；气泡单独计时。循环互动默认在限定时间后结束，睡觉默认 7 秒，拖动结束反馈默认 600 毫秒；拖动中持续保持拖动姿态。静态角色与缺少动作的旧角色包继续使用通用程序变形。

## 4. 六种动作

| 键 | 触发 | 必需 |
|---|---|---|
| `idle` | 待机、动作缺失时回退 | 是，建议循环 |
| `pet` | 摸头、桌宠轻点 | 否 |
| `happy` | 小零食 | 否 |
| `sleepy` | 休息 | 否 |
| `drag` | 桌宠拖动结束后的反馈 | 否 |
| `celebrate` | 庆祝、专注完成 | 否 |

缺少某动作时回退到已有基础动作或待机，保留通用的程序变形和气泡反馈。静态模式只显示单帧，动态序列请明确选择 `sprite`。不支持自定义代码、未知动作名或 Live2D 参数。

### v2：独立动作与变体

把 `schemaVersion` 设置为 `2`，保留原有 `idle` 和皮肤结构，就可以增加以下可选动作：

| 键 | 用途 |
|---|---|
| `stretch` / `look` / `doze` / `stroll` | 伸懒腰、张望、打瞌睡和小幅挪动 |
| `thinking` / `attention` / `error` | 工作中、抬头提醒和困惑；提醒动作播放一次，状态信息继续保留 |
| `blink` / `ear` / `tail` | 待机时独立随机触发；工作中也可做轻微小动作 |

`blink`、`ear` 和 `tail` 及它们的变体必须 `loop: false`。眨眼间隔约 3–7 秒，耳朵约 11–23 秒，尾巴约 8–18 秒；小动作串行播放，隐藏或暂停恢复后重新冷却，不补播积压动作。免打扰下不触发这些小动作。系统“减少动态效果”偏好同时作用于程序变形和逐帧播放。

每个动作仍直接提供 `frames`、`fps`、`loop`，可选 `variants` 数组提供最多 4 个额外版本：

```json
"pet": {
  "frames": [{ "asset": "petLeft" }],
  "fps": 12,
  "loop": false,
  "variants": [{
    "frames": [{ "asset": "petRight" }],
    "fps": 12,
    "loop": false
  }]
}
```

重复互动依次选择不同版本；版本选择由事件序号决定，管理预览与桌宠同步。变体不能再嵌套变体，只能提供动画字段，所有皮肤都必须提供它引用的资源。

循环动作可加 `durationMs`（100–30000 毫秒）指定播放时长；单次动作的时长由帧数 / 帧率决定，不能设置这个字段。工作中和待机是持续状态。待机优先使用缓慢呼吸循环，眨眼等变化单独制作，避免固定在呼吸动画的同一帧。

四种自主行为还可设置 `weight`（0.1–10）和 `cooldownMs`（1000–600000 毫秒）。调度保留最近 5 次记录，降低近期重复动作的权重，不连续选择同一行为，并遵守各自冷却。默认打瞌睡较少且冷却较长；活动范围设为原地时不选择挪动。各动作的冷却与全局活动频率共同生效。

创作流程：先制作统一画布、落脚位置一致的图片 → 在皮肤中声明资源 → 编写动作和变体 → 同时导入 JSON 与 PNG → 在“动作试映”逐个检查并重复点击查看变体 → 让角色来陪伴。图集所有裁剪区域、变体资源与播放参数都会在导入及备份恢复时检查；已有 v1 角色包无需迁移。

## 5. 皮肤

在 `skins` 添加新项即可，每项都需提供相同动作所引用的全部资源键。例如默认皮肤的 `sheet` 对应 `idle-cream.png`，绿色皮肤的 `sheet` 对应 `idle-sage.png`；动作定义可以共用。

皮肤可以换颜色、服装或整套图片。精灵图必须使用相同帧布局，避免同一裁切矩形在另一套皮肤中越界。后续 Live2D 会有独立的资源适配，当前图片包不会自动转换成 Live2D 模型。

## 6. 当前限制

| 项目 | 上限 / 要求 |
|---|---|
| 自定义角色 | 6 个 |
| 单次选择 | 40 个文件，总计 12 MiB |
| JSON 清单 | 256 KiB |
| 角色名称 | 1–40 个字符 |
| 画布 | 宽、高各 16–2048 |
| 图片 | 单边不超过 8192 像素；全部 PNG 共不超过 16,777,216 像素 |
| 皮肤 | 1–4 套，每套最多 32 个资源键 |
| 动作 | 每个 1–120 帧，帧率 1–60 |
| 完整本地状态 | 桌面宿主保存上限 32 MiB，图片转为 Base64 后会增大 |

浏览器体验模式还受浏览器 localStorage 容量限制，大角色请使用桌面版。导入失败会显示原因，保留已选择的角色。图片被复制进应用数据，移除角色不会删除原始素材。
