# Agent 联动使用说明

## v0.9.2：近期读取与积分折合

首次启动先读取最近变化会话尾部的额度、积分与任务状态，默认只补齐近 7 个本地自然日（含今天）的用量。看板显示已完成的近期文件数；较早且未更新的会话不会阻塞近期统计。

旧会话仍在更新时也参与近期统计。对于按时间顺序追加的 Codex JSONL，会定位近期区间并读取之前的累计计数和模型作为基线，避免把历史累计量计入今天；无法可靠取得基线时回退该文件的顺序读取，仍只计入近期事件。进度单独保存，重启继续增量读取。

在 Agent 看板点击“补读更早历史”可开启完整历史扫描，点击“暂停历史补读”保留进度。历史与近期使用独立进度，近期优先；历史账目仍最多保留近 90 天、20,000 条增量记录。补读仅查询本地文件，不调用模型。后台补读采用短批次与短暂停，正常完成后恢复每 10 秒检查；远端额度查询仍遵守独立的 10 分钟限频，DeepSeek 仍最多每 60 秒自动查询。

点击桌宠常显数据框，展开的“任务与用量”小详情面板直接显示 **Codex 积分余额**，无需打开后台管理面板。积分与美元折合在同一行显示为“数值 积分 = $金额”，点击该行展开来源、更新时间与换算说明。较旧的附加额度默认折叠，主额度始终直接显示。后台 Agent 看板也可查看。

常显默认不增加积分行；需要时在“连接与提醒”勾选“常显积分余额”，侧边数据签和底部底座都会显示。简洁状态条可在“状态条附加指标”选择“Codex 积分余额”。

- 详情同时显示原始 credits 和美元折合；常显单位可选美元（默认）或积分。默认参考比例为 $0.04 / credit，在“积分换算设置”中可修改和恢复。参考 [官方 2,500 credits 对应 $100 的说明](https://help.openai.com/en/articles/20001147-codex-credits-for-students-terms-of-service)。折合金额是参考使用价值，非现金余额或实际付款金额。
- 充值、邀请等积分按返回合计展示，不推算来源明细。今日费用预估不会从积分中扣减；修改比例不影响 Token、积分原值和费用预估。数据源返回负余额时保留负值，不截成零。
- 无数据显示 `—`，明确返回零才显示 `0`；超过 15 分钟或采集暂停标记待更新。查询失败保留旧值，并在详情标明来源、时间和错误。
- 复用现有本地日志和实时额度查询：不增加独立轮询，不调用模型。实时查询最多每 10 分钟一次，失败后逐步延长至最多 60 分钟；日志较新时会延后查询。
- 最近变化的 8 个会话优先读取尾部快照，每个最多 1 MiB；文件大小未变时不重复读取尾部。尾部快照不累计 Token，完整用量由近期读取流程统计。未找到记录时等待后续日志或成功的实时查询。

数据字段参考 [Codex App Server 官方文档](https://learn.chatgpt.com/docs/app-server)。独立 CLI 未登录时只能读取已有日志快照，Codex 应用内能读到余额不代表桌宠的独立查询也已认证。

## v0.7.0 侧边数据签

默认在角色旁常显任务状态、主额度、今日预估与 Token。周 / 5h 额度并排，各用独立进度条；缺失窗口不补成 100%，Spark 留在点击展开的详情中。常显与详情使用同一份本地快照，不增加网络查询或模型调用。

在“连接与提醒 → 桌宠常显样式”切换到“简洁状态条”可继续使用原来的附加指标。“显示桌宠任务与用量”开关控制整体显隐。

## v0.6.0 美元预估

看板增加今日、近 7 天及各来源/模型的预估美元金额；桌宠附加指标可选择“今日美元预估”。配置模型单价后按当前单价重算保留记录，来源和模型精确匹配。未计价/明细异常记录会单独提示，不当作免费；明细中的缓存和推理不重复相加。

计算公式：`((输入 − 缓存输入) × 输入单价 + 缓存输入 × 缓存单价 + 输出 × 输出单价) / 1000000`，单价为 USD / 百万 token。无需账单权限，不新增 API 调用或日志轮询。它是按所选单价的文本用量参考，不是实际账单或 Pro 套餐美元剩余额度；长上下文、速度档位、缓存写入和额外工具等差异未自动计入。

内置四个 Codex 模型的标准短上下文参考价来源：[OpenAI API 价格页](https://developers.openai.com/api/docs/pricing)，核对日期 2026-09-15；可以手工修改或补充其它模型。保存单价会重算历史，不作为历史账单存证。

## v0.4.0 接入助手

看板内新增本机日志检测和事件通道自检。自检通过实际的本机鉴权接口，但不写任务和账目；“已收到外部事件”只在收到有效事件后显示。收到事件不是持续在线证明，重启后重新检测。

“让 Agent 发送事件”中可复制 PowerShell 手动测试命令，脚本应与 EXE 放在同一目录。手动测试来源为 `manual-test`，会留下一条测试任务，不写入 token；不能据此认定 Codex 审批 Hook 已接入。未保存的连接设置会阻止助手操作，避免覆盖正在编辑的内容。

## v0.3.0 桌宠显示与演示

名字下方新增常驻任务状态条，点击可展开用量详情、打开完整看板。附加指标在“连接与提醒”中选择，也可以关闭状态条。

管理面板“Agent 看板”最上方提供五种联动演示，10 秒后恢复，可随时停止。演示通过应用内部事件同步，不联网、不写入任务或账本。真实通知会打断演示；免打扰下只显示状态。工作中、待确认、完成和失败分别使用不同动作，旧角色包无需更新。

本地日志采集和动画不调用模型、不消耗 token。余额和实时额度查询可能联网；分享、运行要求及详细开销说明见发布包 `START-HERE.md`，或项目文档 `08-sharing.md`。

## Codex

打开“Agent 看板”，默认只读 `CODEX_HOME`，未设置时读取用户目录下的 `.codex`。可在连接设置中指定其它绝对路径。采集每 10 秒检查 `sessions` 与 `archived_sessions` 下的 `rollout-*.jsonl`。

- token 来自累计计数的增量：输入已包含缓存，输出已包含推理，不再相加。累计值归零后按新的计数周期统计，重复快照不重复计费。
- 首次补读和重启不重放历史完成气泡。最多保留近 90 天、20,000 条用量记录，图表为保留记录中的今日与近 7 个本地自然日。v0.9.2 起默认近期优先，更早历史手动开启；没有新记录时不反复写入整个账本。
- 日志可能延迟写入或格式变化，状态是最后观察值。超过 30 分钟的运行 / 等待状态标为待核实。关闭采集保留历史数据。
- 额度百分比是日志最近快照；超过 15 分钟标记可能过期。手动“查询实时额度”只启动官方 CLI 的查询接口，不会启动 / 恢复用户任务。
- 本机 Codex `0.154.0-alpha.6.2` 的独立 App Server 目前返回未认证：应用登录不一定共享给 CLI。此时仍显示日志快照与错误，不能将其视为实时查询成功。
- 日志格式属于兼容适配，未来版本可能需调整；这里不是 OpenAI 账单或完整成本报告。

## DeepSeek

在看板底部输入 API Key，选择“保存密钥”。密钥保存到 Windows 凭据管理器，凭据名称为应用标识加 `.deepseek`，并自动开启每 60 秒余额查询。只请求官方 `https://api.deepseek.com/user/balance`，不发送模型推理请求。可手动刷新或移除密钥。

余额、赠送余额、充值余额保留原币种。今日余额下降仅累加同币种、同一天相邻成功采样的下降值；充值增加不计为消耗，跨日重新建立基线。其它应用消费、赠送金到期及采样间隔都会影响数值，因此它不是当前 Agent 的费用。

低余额在进入阈值时提醒一次，余额恢复后可再次提醒。每日预算达到阈值每天提醒一次，预算 0 为关闭。免打扰时丢弃气泡。更换或移除密钥会清除旧账户余额历史。

本版没有用户真实密钥，真实账户余额联调仍待配置后核验。已验证官方响应格式、错误处理、凭据读写和本地账本逻辑。

## 通用本地事件接口

在连接设置中启用本地事件接口。应用只监听 `127.0.0.1` 随机端口，用随机 Bearer 令牌鉴权。`agent-bridge.json` 位于应用数据目录，包含地址和令牌；勿分享该文件。每次启动生成新令牌。

发布目录附 `send-agent-event.ps1`，例如从 PowerShell 运行：

```powershell
./send-agent-event.ps1 -Source 'my-agent' -SessionId 'session-1' -TurnId 'turn-1' -Status completed
```

需要启动、完成、失败、待确认或中断时发送对应状态 `running`、`completed`、`failed`、`waiting`、`interrupted`。事件只影响看板和气泡，不能执行命令或批准操作。重试请传相同 `-EventId`，避免重复事件。

直接调用接口时，POST `/v1/events`，JSON 示例：

```json
{"eventId":"unique-event-id","source":"my-agent","sessionId":"session-1","turnId":"turn-1","status":"completed","timestamp":1789459200000,"model":"model-name","tokens":{"input":80,"cached":20,"output":20,"reasoning":10,"total":100}}
```

`timestamp` 换成当前 Unix 毫秒；允许过去 24 小时至未来 5 分钟。标识只允许 ASCII 字母、数字、点、横线、下划线、冒号。`tokens` 和 `model` 可省略。用量必须是该事件新增值，不是会话累计值；`total=input+output`。来源 `codex` 的事件不允许带 tokens，避免与日志重复。

限制：请求体 8 KB、每分钟 120 请求、拒绝网页 Origin、拒绝分块传输。接口默认关闭。DSH / Claude Code 等可按此协议接入；本版未验证其原生插件，不宣称已自动连通。

## 可选 Codex 审批 / 生命周期钩子

`codex-hook.ps1` 将 UserPromptSubmit / PermissionRequest / Stop / Interrupt 转成状态事件，仅读取会话和轮次标识。未提供 turn_id 时记录为 `hook-session`，不猜测日志轮次；这时日志和钩子可能各有一条任务。

按你当前 Codex 版本的 [官方 Hooks 文档](https://learn.chatgpt.com/docs/hooks) 添加 command hook，命令调用发布目录中该脚本的**绝对路径**，如：

```text
powershell.exe -NoProfile -File "E:\DesktopPet\codex-hook.ps1"
```

推荐在已安装 PowerShell 7 时将可执行文件改为 `pwsh`。分别为上述事件配置该命令。保留现有 hooks，合并配置而不是覆盖。通过 Codex 的 `/hooks` 检查并信任配置；桌宠不会替你绕过钩子信任、审批或执行策略。钩子总是返回空 JSON，不批准 / 拒绝任何工具请求。实际客户端 Hook 触发链仍需在用户启用后核验。

## 数据与隐私

应用数据默认在 `%APPDATA%\com.desktop-pet.companion`。联动数据单独保存在 `integrations.json` 和备份中，包括用量数值、时间、模型、任务标识、采集游标、配置、余额历史和提醒收件箱，不保存聊天正文或 API Key。只读日志解析过程会短暂接触完整 JSON 行；超 1 MB 的行跳过。角色包和角色/偏好备份不包含密钥或联动历史。

## 提醒收件箱

v0.5.0 起，已开启的完成、失败、待确认和余额提醒会保留在左侧“提醒收件箱”，可切换已读与未读、全部已读或清理已读。最多保存最近 90 天的 300 条；免打扰抑制气泡和声音，但仍保存提醒。关闭某类提醒后，其新消息不再记录；首次补读历史、联动演示和通道自检不进入收件箱。

桌宠任务状态详情显示未读数，点击即可打开收件箱。该功能使用现有采集快照，不新增模型调用、日志轮询或远端查询。

余额请求使用 Windows 网络代理设置。读取本地日志和接收本机事件无需外网。程序关闭后不再采集。
