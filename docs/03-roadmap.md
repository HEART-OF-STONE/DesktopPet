更新日期：2026-09-15。已交付 v0.1.0 可运行原型，完成 M0–M2 的主要功能路径；桌面鼠标交互、DPI/多屏、休眠与长期运行尚未完成验收，M3 未完成。勾选项表示该任务的当前功能已实现并有对应检查；未勾选项可能已有部分实现，具体见 `05-implementation-status.md`。

v0.1.1 追加：昵称和默认名字可编辑，已通过双窗口同步与完整进程重启验证；第一版源码已开始本地 Git 版本管理。

已确定：V1 = 静态图片加程序变形 + 逐帧 2D + 基础陪伴功能。Live2D 在 V1 之后接入。

**范围修正（2026-09-15）**：V1 还应包含参考项目的核心 Agent 联动和用量看板，Codex 优先，其次实际余额来源。已新增 M2b / DP-601～DP-608，详见 `06-agent-integration.md`。以下原始 5–8 周估算尚未包含这部分工作，应在接口验证后重新估算。

## 1. 时间估算口径

以下按一位熟悉所选技术的开发者、每周约 25–30 小时有效开发、使用现成且许可明确的基础素材估算。时间含基础验证，不包含从零学习 Rust、角色绘制/绑定、素材返工和外部许可审核等待。

- V1 双模式陪伴 MVP（M0–M2）：约 4–6 周，包含静态/逐帧角色切换与基础资源管理。
- V1 对外发布加固（M3）：额外约 1–2 周；可发布首版合计约 5–8 周。
- 后续 AI 文本聊天与受限工具（M4）：额外约 2–3 周。
- 后续一个内置 Live2D 角色与基本表情适配（M5）：额外约 1–2 周工程时间，启动该阶段后再验证模型与 SDK，重新估算发布工作。

这是工程粗估，M0 完成后根据实测重新估算。M4 与 M5 的先后可按需要调整，均在 V1 之后；公开任意 Live2D 导入没有固定交付日期，需要在后续阶段确认其发布条件。

## 2. 里程碑

| 阶段 | 预计投入 | 交付物 | 进入下一阶段的条件 |
|---|---|---|---|
| M0 技术与素材验证 | 3–5 个工作日 | 透明窗口原型、静态图变形与少量逐帧样例、测量记录 | 窗口交互可行，两种 2D 形式可显示，框架选择明确 |
| M1 桌面底座 | 约 1 周 | 拖动、穿透、吸附、托盘、缩放、设置、位置恢复 | 常用桌面操作不被阻挡，角色可找回 |
| M2 双模式陪伴 MVP | 约 2–3 周 | 六种语义动作、双模式角色导入/切换、皮肤、气泡、计时、免打扰、离线保存 | 两种模式共用功能，动作降级可靠，陪伴闭环完成 |
| M2b Agent 联动与用量看板 | 接口验证后估算 | Codex 用量/额度、任务反馈、DeepSeek 余额和预警、通用事件边界 | 真实数据可核验，不同口径不混淆，提醒不会重复轰炸 |
| M3 V1 发布加固 | 约 1–2 周 | 安装包、迁移/备份、使用说明、诊断、试用版本 | 真机矩阵通过，V1 代码与图片/音频资源的发布条件满足 |
| M4 AI 与工具 | 约 2–3 周 | 文本对话、人设、可管理记忆、受限计时意图 | 密钥与权限边界有效，断网不影响桌宠 |
| M5 Live2D 扩展 | 接入粗估 1–2 周 | SDK 样例、适配器、一个内置模型与已有皮肤；发布另验收 | 模型与 SDK 发布条件满足，原有 2D 角色持续可用 |

V1 到 M3 完成交付，不依赖 AI 或 Live2D。首版准备静态与逐帧两个示例包，可复用同一角色形象。

## 3. 第一周安排

### 第 1 天：建立可运行窗口

- 确认 Node、包管理器、Rust、Windows 构建依赖，锁定正式稳定版本。
- 初始化 Tauri + React + TypeScript。
- 创建透明无边框小窗口，显示一张项目自有或许可明确的占位图。
- 提供托盘退出与找回，不要求最终美术。

验收：开发运行和打包运行均可显示，退出后进程结束。

### 第 2 天：交互可行性

- 角色本体点击、按住拖动、透明区域穿透。
- 检查拖动阈值、焦点保持和菜单可操作。
- 避免使用全屏透明窗口作为默认方案。

验收：点击透明区域能正常操作后方应用；触摸角色有反馈，拖动不中断。

### 第 3 天：多屏与恢复

- 验证 100% / 150% / 200% 缩放和跨屏。
- 验证负坐标副屏、拔掉副屏、睡眠后恢复。
- 记录坐标约定和找回行为。

验收：宠物、命中区域和气泡锚点对齐；丢失显示器后宠物仍能找回。

### 第 4 天：两种 2D 表现样例

- 静态图实现按下压扁、松开回弹、左右翻转。
- 使用少量许可明确的动画帧，验证逐帧循环、单次动作和返回待机。
- 用相同接口触发动作，切换角色后保留窗口位置与设置。
- 记录帧率、图片尺寸和解码后内存，检查换帧锚点不跳动。

验收：静态图与逐帧两种模式都能响应同一交互；播放速度与屏幕刷新率无关。

### 第 5 天：决策与下一阶段准备

- 记录 CPU、内存和稳定性基线。
- 若 Tauri 的关键桌面能力不达标，做有范围的 Electron 对照验证并定下宿主。
- 确定首个角色清单、动作语义、资源来源。
- 根据实际困难调整 M1–M3 估算。

验收：有一个可演示的桌面原型，以及明确的技术选择依据。

## 5. MVP 验收矩阵

| 场景 | 通过标准 |
|---|---|
| 首次启动 | 无需联网或 API Key 即可见到角色 |
| 静态角色 | PNG 可加载，按压、回弹、摇摆和翻转正常，结束后恢复 |
| 逐帧角色 | PNG 序列与精灵图按清单播放；循环、单次、打断和恢复正确 |
| 动画时序 | 不同刷新率下动作时长一致；隐藏恢复不补播过期动作 |
| 角色与皮肤 | 两种角色类型可相互切换，匹配的皮肤正常播放，旧资源释放 |
| 点击与拖动 | 不串成错误动作，不误触后方应用 |
| 透明区域 | 后方应用点击与输入正常 |
| 焦点 | 待机和普通提醒不打断正在输入的窗口 |
| 贴边 | 角色与气泡可见，文字不随角色镜像反转 |
| 缩放与多屏 | 点击区域匹配画面，无跳动或失踪 |
| 恢复 | 重启保留设置，副屏断开可找回 |
| 计时 | 正常、暂停、休眠、重启场景符合定义，到期不重复 |
| 免打扰 | 不产生闲聊和音效，明确的到期提醒按用户策略处理 |
| 断网 | 基础陪伴和本地计时不受影响 |
| 资源异常 | 无效角色包给出原因，继续使用旧角色或占位图 |
| 长时间运行 | 8 小时无崩溃，资源不持续增长 |
| 安装与退出 | 干净用户环境可运行；退出释放进程；数据位置明确 |

Live2D 阶段追加：表情与眨眼叠加、两种模型切换、已有皮肤切换、缺少动作降级、隐藏恢复、图形上下文恢复、连续切换后的内存趋势。

AI 阶段追加：错误密钥、超时、取消生成、服务不可用、预算触发、无效工具参数、记忆删除与导出不含密钥。

## 6. 风险与处理次序

| 风险 | 触发信号 | 应对 |
|---|---|---|
| 功能越加越多 | MVP 尚未日用就开始语音、商城、多宠物 | 先完成 M2 验收，后续想法进入候选清单 |
| 桌面交互不稳 | 透明处挡点击、抢焦点、多屏失踪 | M0 先验证，必要时切宿主 |
| 美术延迟 | 逐帧资源缺动作、皮肤帧不齐 | 用静态图反馈降级，采用少量样例帧推进软件 |
| Live2D 发布路径不清（后续） | 希望公开支持任意模型导入 | 在 M5 核对规则，将开放导入作为独立发布节点 |
| 常驻耗电 | 空闲仍高频更新、隐藏后持续绘制 | 统一动画循环、低帧率、暂停隐藏窗口、释放面板 |
| AI 费用失控 | 被动行为不断请求模型 | 本地驱动基础行为，请求触发与预算集中控制 |
| 数据迁移损坏 | 升级后设置或记忆丢失 | 版本化迁移、备份、失败保留原文件 |

## 7. 后续候选，不计入首版承诺

- 语音：先按键说话和朗读，再考虑持续语音交互。
- 桌面感知：用户主动截取指定区域，不先做后台持续截图。
- 更多余额厂商：核心余额看板已进入 M2b；额外平台按真实需求逐个接入。
- 更多 Agent：Codex 与通用任务事件已进入 M2b；其余来源独立验证兼容性。
- 多宠物：独立实例与角色间互动，同时重新评估窗口和性能模型。
- 创作者工具：角色包检查器、动作映射编辑器、素材预览；市场在分发与许可稳定后讨论。
- 第三方代码插件：独立进程或合适的受限执行环境，配套权限和版本治理，另立设计文档。
- 云同步：按用户需求独立设计账号、冲突、删除和加密策略。

下一步先完成 DP-003～DP-005 的真实鼠标、多屏/DPI 和休眠验收，记录 CPU/内存基线；再完善动作优先级、气泡队列和数据迁移，之后推进 M3 安装与试用。当前先用自有演示角色验证体验，角色美术和名称可随用户反馈替换。
